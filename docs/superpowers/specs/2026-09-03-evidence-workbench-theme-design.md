# 证据工作台视觉主题设计

## 目标

将现有简历匹配平台从通用的白底蓝色卡片界面，升级为“证据工作台”主题。界面应让用户快速完成上传、岗位描述输入、匹配任务跟踪、证据审阅、模型配置和简历生命周期操作，同时通过证据来源、状态和风险的视觉层级体现产品可信度。

## 设计方向

- 模式：Operate，优先保证扫描、输入、比较和恢复操作效率。
- 视觉隐喻：招聘分析师的证据台账与审阅工作区。
- 主色：石墨、冷白、深青绿；琥珀、珊瑚仅用于警告、缺口、失败和危险操作。
- 质感：细线分隔、紧凑编号、来源标尺和明确状态，不使用大面积渐变、紫色主色或嵌套卡片。
- 字体：系统无衬线用于界面文字，等宽字体只用于业务 ID、字符范围和代码/配置内容。
- 动效：仅用于任务状态变化、通知出现和按钮反馈，时长控制在 150-250ms。

## 页面应用

- 全局导航保留品牌、当前用户和退出登录；增加清晰的工作区导航状态，但不改变路由。
- 登录/注册/找回密码使用安静的单列表单，突出错误、成功和恢复动作。
- 有效简历页使用列表台账结构，标题、版本、更新时间和动作保持可扫描。
- 上传匹配页将输入表单、模型选择、岗位描述和任务状态作为同一工作流的连续区域。
- 匹配报告页突出综合匹配度、五项分项分数、岗位要求证据和逐项审核建议；状态颜色必须同时有文字说明。
- 模型配置页突出供应商、模型、连接状态和密钥不可回显约束；TOML 作为高级编辑入口，而不是唯一配置方式。
- 恢复、删除确认、超时、空数据和失败页面沿用统一状态语言和焦点样式。

## 兼容边界

本次只修改 `front/src` 的视觉令牌、布局类和必要的语义包装。不得修改：

- Vue Router 路径和路由守卫；
- Java/Python API、OpenAPI/JSON 字段和错误码；
- Pinia 状态、权限判断、任务轮询和生命周期操作；
- 现有 `data-test` 属性、表单字段名称和测试可定位结构。

## 验收证据

- 所有现有路由仍可通过原入口访问，登录后页面不出现空白。
- 业务状态至少覆盖默认、悬停、聚焦、禁用、加载、成功、失败、超时、空数据和删除确认。
- 1440px 桌面和 390px 移动宽度下无横向溢出，报告证据表可横向滚动且操作区不被遮挡。
- 颜色对比度满足正文 4.5:1、大字号 3:1；键盘焦点可见。
- Impeccable detector 仅对修改后的前端目标运行一次；项目完整测试交由用户按既有规则执行。

## 非目标

- 不新增后端能力、岗位类型或模型供应商。
- 不替换现有业务文案，不自动生成新的匹配结果。
- 不在本次改造中重写业务组件逻辑。
